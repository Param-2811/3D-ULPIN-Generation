# 3D ULPIN specification

## Background

India's existing ULPIN is a **14-digit number** generated by DoLR from the geo-referenced
coordinates of a land parcel's vertices, following the ECCMA and OGC standards. NIC's
BhuNaksha software generates it from a georeferenced revenue village shapefile.

It is **2D only**. It identifies the ground, not what is above or below it.

## Our design principle

**Extend, do not replace.** The existing 14-digit ULPIN stays intact as the parent ID. We
append a vertical hierarchy to it. This means our system works alongside India's current
land records instead of demanding they be thrown away — state this explicitly to judges.

## Format

```
<PARENT_ULPIN>-<BUILDING>-<LEVEL>-<UNIT>-<CHECK>
```

| Segment | Length | Format | Example | Meaning |
|---|---|---|---|---|
| PARENT_ULPIN | 14 | digits | `27021500123456` | the existing 2D land parcel ID |
| BUILDING | 3 | `B` + 2 digits | `B01` | which building on that parcel |
| LEVEL | 3 | see below | `F05` | which vertical level |
| UNIT | 3 | letter + 2 digits | `U03` | which unit on that level |
| CHECK | 1 | digit | `4` | Luhn check digit over the whole string |

### LEVEL codes

| Code | Meaning |
|---|---|
| `G00` | ground floor |
| `F01`–`F99` | above-ground floors |
| `B01`–`B09` | basement levels (below ground) |
| `R00` | roof / terrace |
| `A01`–`A09` | air rights volume above the building |

Note: `B` is reserved for basement in the LEVEL segment and for building in the BUILDING
segment. They never collide because position is fixed.

### UNIT codes

| Prefix | Meaning |
|---|---|
| `U` | residential or commercial unit (apartment, shop) |
| `P` | parking slot |
| `C` | common area (lobby, stairwell, lift) |
| `T` | utility or tunnel volume |

## Examples

Check digits below are real, computed by `src/ulpin/generate.py` (Luhn over the 22 digits).

```
27021500123456-B01-F05-U03-4   Apartment 3, 5th floor, building 1
27021500123456-B01-B01-P12-4   Parking slot 12, basement level 1
27021500123456-B01-G00-C01-9   Ground floor lobby
27021500123456-B00-B02-T01-7   A water main crossing under the parcel (no building)
27021500123456-B01-A01-U01-7   Air-rights volume above building 1
```

`B00` in the BUILDING segment means "not attached to any building" — used for utility
networks, tunnels, and metro corridors crossing under the parcel.

## Rules

1. **Deterministic.** The same physical volume must always yield the same ID. Never use
   random numbers, timestamps, or UUIDs.
2. **Stable under re-processing.** Re-running the pipeline on unchanged input must produce
   identical IDs. Derive sequence numbers from a fixed ordering rule: units are numbered
   clockwise starting from the unit whose centroid is furthest north-west.
3. **Check digit** computed with the Luhn algorithm over all digits in the string, so a
   mistyped ID is rejected rather than silently pointing at the wrong flat.
4. **Uppercase only.** No lowercase, no spaces.
5. **Every ID maps to exactly one 3D volume**, and every 3D volume has exactly one ID.

## Required functions in `src/ulpin/generate.py`

```python
generate(parent_ulpin, building_no, level_code, unit_code) -> str
parse(ulpin_3d) -> dict          # reverse of generate
validate(ulpin_3d) -> bool       # format + check digit
```

`parse(generate(x)) == x` must hold for all valid inputs. Test it.

## What to say to judges about this

- It is backward compatible — the first 14 digits are the official ULPIN unchanged.
- It is human readable — an officer can read the ID and know it is flat 3 on floor 5.
- It is error resistant — the check digit catches typos at data entry.
- It covers what the problem statement's background section asks for but the description
  omits: parking, air rights, and underground utility corridors.
